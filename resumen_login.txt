
Qué contiene
- login.html:
  - estructura básica HTML
  - formulario con:
    - correo empresarial
    - contraseña
    - botón “Ingresar”
  - área para mensajes de error o éxito

- login.css:
  - diseño moderno con tarjeta centrada
  - colores para mensajes de error/success
  - estilos para la fuerza de contraseña
  - botón principal y estados visuales

- login.js:
  - lista de contraseñas comunes
  - validación de fortaleza
  - validación de email
  - bloqueo de contraseñas muy débiles
  - redirección a Derechos.html al iniciar sesión

Características
- Validación básica:
  - email debe incluir “@”
  - contraseña mínima 8 caracteres
  - si es muy débil, muestra error
- Fuerza de contraseña:
  - Weak / Medium / Strong
  - usando mensajes con iconos y clases CSS
- Seguridad simple:
  - compara la contraseña contra una blacklist de contraseñas comunes
  - también bloquea combinaciones basadas en email y empresa
- Sin registro:
  - el comentario del archivo dice: “LOGIN SIN REGISTRO”
  - no hay base de datos, backend, JWT, cookies ni localStorage
- Simulación de login:
  - si todo parece correcto, muestra “Inicio de sesión exitoso”
  - abre una nueva pestaña con la página de derechos
  - intenta cerrar la ventana de login

Funcionamiento
1. El usuario escribe email y contraseña.
2. En cada cambio, el código evalúa la fuerza de la contraseña.
3. Al enviar el formulario:
   - valida si el correo tiene formato básico
   - valida si la contraseña es “muy fácil”
4. Si pasa, muestra un mensaje de éxito.
5. Después de 300 ms:
   - abre Derechos.html
   - intenta cerrar la pestaña actual
   - si eso falla, reemplaza el contenido con un aviso de “Sesión iniciada”

Errores o problemas a futuro
- No es autenticación real:
  - cualquier email con “@” puede pasar
  - no existe verificación con servidor
  - no hay usuarios ni credenciales reales
- No hay persistencia:
  - no guarda sesión, no usa token, no usa cookies ni almacenamiento seguro
- La seguridad del lado cliente es fácil de evadir:
  - un usuario puede ejecutar JavaScript en el navegador y saltarse la validación
- window.close() puede no funcionar:
  - muchos navegadores bloquean cerrar la pestaña si fue abierta por el usuario manualmente
- Ruta dependiente:
  - si Derechos.html no existe o no está en el mismo sitio, la navegación falla
- Validación débil del correo:
  - email.includes('@') no comprueba dirección real o dominio válido
- No hay manejo de errores robusto:
  - no controla caso de red, servidor caído, páginas inexistentes, errores de navegador
- No hay protección contra ataques:
  - no hay rate limiting, no hay bloqueo por intentos fallidos, no hay hashing de contraseña
- El código asume que se ejecuta en navegador normal:
  - puede fallar si es ejecutado desde un entorno no visual o de modo local restringido

En resumen
- Es una demostración visual de login, no un sistema seguro.
- Está bien para maquetación o prototipo.
- Para producción haría falta:
  - backend real
  - base de datos
  - hash de contraseñas
  - sesiones o JWT
  - validación del lado servidor
  - redirección segura y manejo de errores
